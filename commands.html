AZ-104 Exam Critical Rules:

  • Microsoft Graph for Entra objects: Use the Microsoft.Graph PowerShell SDK for Entra user and group management. For user creation, the current exam-relevant pattern is Connect-MgGraph -Scopes "User.ReadWrite.All" followed by New-MgUser with a PasswordProfile, AccountEnabled, MailNickName, and UserPrincipalName. Guest invitations use New-MgInvitation.
  • Role Definition File: Custom roles require explicit Actions, NotActions, and AssignableScopes. AssignableScopes can be defined at management groups, subscriptions, or resource groups, but not individual resource scopes.
  • Lock Inheritance: CanNotDelete prevents deletion; ReadOnly prevents modifications and deletions (e.g., reading storage account keys is blocked under ReadOnly because key retrieval is an HTTP POST action).
  • Tagging Behavior: Tags are not inherited down to nested child resources automatically. Use Azure Policy to enforce tag inheritance.

Provision Storage Account az storage account create -g <rg> -n <stName> -l eastus --sku Standard_GRS --kind StorageV2 --min-tls-version TLS1_2 New-AzStorageAccount -ResourceGroupName <rg> -Name <stName> -Location "eastus" -SkuName "Standard_GRS" -Kind "StorageV2" -MinimumTlsVersion "TLS1_2"
Account Access Key Rotation az storage account keys renew -g <rg> -n <stName> --key key2 New-AzStorageAccountKey -ResourceGroupName <rg> -Name <stName> -KeyName "key2"
Blob Tier Lifecycle & Rehydration az storage blob set-tier -c "archive-container" -n "doc.pdf" --tier Cool --rehydrate-priority High --account-name <stName> $blob = Get-AzStorageBlob -Container "archive-container" -Blob "doc.pdf" -Context $ctx
$blob.BlobClient.SetAccessTier("Cool", $null, "Standard")
For Archive → Hot/Cool rehydration, use the target tier and appropriate rehydrate priority.
Stored Access Policy (SAP) az storage container policy create --account-name <stName> -c "data" -n "ReadPolicy" --permissions r --expiry 2026-12-31T23:59:00Z New-AzStorageContainerStoredAccessPolicy -Container "data" -Policy "ReadPolicy" -Permission "r" -ExpiryTime "2026-12-31T23:59:00Z" -Context $ctx
User Delegation SAS Token az storage container generate-sas --account-name <stName> -n "data" --permissions r --expiry 2026-12-31T23:59:00Z --auth-mode login --as-user $userCtx = New-AzStorageContext -StorageAccountName <stName> -UseConnectedAccount
New-AzStorageContainerSASToken -Name "data" -Permission r -Context $userCtx
Azure File Share & Quota az storage share create --account-name <stName> -n "smbshare" --quota 1024 New-AzStorageShare -Name "smbshare" -QuotaGiB 1024 -Context $ctx

AZ-104 Exam Critical Rules:

  • SAS Security: A User Delegation SAS uses Entra ID credentials and is more secure than Account or Service SAS tokens backed by storage access keys.
  • Stored Access Policy: Modifying or deleting a Stored Access Policy immediately revokes all active SAS tokens associated with that policy without needing to regenerate storage account keys.
  • Blob Rehydration: Changing a blob from Archive to Hot/Cool requires rehydration. High priority rehydration processes faster but costs more.

VMSS Autoscale Rule Provisioning az monitor autoscale create -g <rg> --resource "VMSS01" --resource-type "Microsoft.Compute/virtualMachineScaleSets" --min-count 2 --max-count 10 --count 2 $rule = New-AzAutoscaleRule -MetricName "Percentage CPU" -MetricTriggerThresholdOperator GreaterThan -MetricTriggerThreshold 70 -ScaleActionDirection Increase -ScaleActionValue "1"
Add-AzAutoscaleSetting -ResourceGroupName <rg> -Name "ScaleOutRule" -TargetResourceId <vmssId> -AutoscaleRule $rule

AZ-104 Exam Critical Rules:

  • Resize Constraints: Resizing a VM to a series supported by the current host cluster can happen while running; otherwise, the VM must be Deallocated first.
  • VMSS Upgrades: Scale Sets with Manual upgrade policies require explicitly running az vmss update-instances to roll out new image versions to existing instances.
Networking (15–20% of Exam Scope)
Networking CLI Docs ↗
Scenario / Action Azure CLI Syntax (`az`) Azure PowerShell Syntax (`Az`)
VNet & Subnets Setup az network vnet create -g <rg> -n "VNet1" --address-prefixes 10.0.0.0/16 --subnet-name "Frontend" --subnet-prefixes 10.0.1.0/24 $sub = New-AzVirtualNetworkSubnetConfig -Name "Frontend" -AddressPrefix "10.0.1.0/24"
New-AzVirtualNetwork -ResourceGroupName <rg> -Name "VNet1" -AddressPrefix "10.0.0.0/16" -Subnet $sub
NSG Priority Rule Setup az network nsg rule create -g <rg> --nsg-name "NSG-Web" -n "AllowHTTP" --priority 100 --direction Inbound --access Allow --protocol Tcp --destination-port-ranges 80 $nsg = Get-AzNetworkSecurityGroup -ResourceGroupName <rg> -Name "NSG-Web"
$nsg | Add-AzNetworkSecurityRuleConfig -Name "AllowHTTP" -Priority 100 -Direction Inbound -Access Allow -Protocol Tcp -DestinationPortRange 80 | Set-AzNetworkSecurityGroup
Bi-directional VNet Peering az network vnet peering create -g <rg> -n "VNet1-to-VNet2" --vnet-name "VNet1" --remote-vnet <vnet2Id> --allow-vnet-access --allow-forwarded-traffic $vnet1 = Get-AzVirtualNetwork -ResourceGroupName <rg> -Name "VNet1"
$vnet2 = Get-AzVirtualNetwork -ResourceGroupName <rg> -Name "VNet2"
Add-AzVirtualNetworkPeering -Name "VNet1-to-VNet2" -VirtualNetwork $vnet1 -RemoteVirtualNetworkId $vnet2.Id -AllowVirtualNetworkAccess -AllowForwardedTraffic
Add-AzVirtualNetworkPeering -Name "VNet2-to-VNet1" -VirtualNetwork $vnet2 -RemoteVirtualNetworkId $vnet1.Id -AllowVirtualNetworkAccess -AllowForwardedTraffic
User-Defined Route (UDR) Override az network route-table create -g <rg> -n "RT-NVA"
az network route-table route create -g <rg> --route-table-name "RT-NVA" -n "DefaultToNVA" --address-prefix 0.0.0.0/0 --next-hop-type VirtualAppliance --next-hop-ip-address 10.0.2.4		 $route = New-AzRouteConfig -Name "DefaultToNVA" -AddressPrefix "0.0.0.0/0" -NextHopType "VirtualAppliance" -NextHopIpAddress "10.0.2.4"
New-AzRouteTable -ResourceGroupName <rg> -Name "RT-NVA" -Route $route
Private Endpoint Creation az network private-endpoint create -g <rg> -n "PE-Storage" --vnet-name "VNet1" --subnet "Frontend" --private-connection-resource-id <stId> --group-id blob --connection-name "PE-Conn" $sub = Get-AzVirtualNetwork -ResourceGroupName <rg> -Name "VNet1" | Get-AzVirtualNetworkSubnetConfig -Name "Frontend"
$link = New-AzPrivateLinkServiceConnection -Name "PE-Conn" -PrivateLinkServiceId <stId> -GroupID "blob"
New-AzPrivateEndpoint -ResourceGroupName <rg> -Name "PE-Storage" -Subnet $sub -PrivateLinkServiceConnection $link

AZ-104 Exam Critical Rules:

  • Routing Order: Traffic routes according to Longest Prefix Match (LPM) first. If two routes match identically, UDR overrides Default System Routes.
  • Subnet IP Allocation: Azure reserves 5 IP addresses per subnet (first 4 and last 1). E.g., for 10.0.0.0/24, 10.0.0.0 through 10.0.0.3 and 10.0.0.255 are reserved.
