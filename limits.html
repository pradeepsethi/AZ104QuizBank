Identity & Governance (20–25% of Exam)
Microsoft Entra Limits ↗
Resource / Concept Limit / Quota Type AZ-104 Exam Focus
Management Group Depth Max 6 levels deep (excluding root) Hard Root management group controls tenant-wide settings.
Resource Locks Max 20 locks per scope Hard Locks override RBAC permissions and do NOT inherit from Management Groups.
Resource Tags Max 50 tags per resource / RG / sub Hard Tags do NOT automatically inherit down to child resources.
RBAC Role Assignments Max 4,000 assignments per subscription Hard Assign permissions to Entra ID Groups instead of single users to avoid hitting limits.
Custom RBAC Roles Max 5,000 custom roles per tenant Hard AssignableScopes controls where a custom role can be used.
Azure Policy Assignments per Scope Max 200 initiatives/policies per scope (subscription or resource group) Hard Evaluated hierarchically from Management Group down to Resource Group.
Microsoft Entra Guest Users Up to 5x ratio of paid tenant users (Free tier default) Soft External collaboration limits scale based on Microsoft Entra external identities tier.

Operational Restrictions:

  • Azure Policy: Evaluates resources on creation or update. Policy does not automatically modify non-compliant resources unless a Remediation Task is configured.
  • Azure Budgets: Fires action group alerts when threshold limits are breached, but does not auto-stop or delete resources.
  • Self-Service Password Reset (SSPR): Requires writeback to be enabled if syncing with on-premises Active Directory.
  • Access Reviews: Periodic reviews of group memberships and guest access require Microsoft Entra ID P2 licenses.
Storage (15–20% of Exam)
Azure Storage Scalability Limits ↗
Resource / Concept Limit / Quota Type AZ-104 Exam Focus
Storage Accounts per Region Max 250 per subscription Soft Can request limit increases by opening a free support request.
Storage Account Capacity Max 5 PB per storage account Soft Applies across Blobs, Files, Queues, and Tables combined.
Access Keys 2 active keys (Key1 and Key2) Hard Use zero-downtime rotation: update apps to Key2, regenerate Key1, then swap apps back.
Stored Access Policies Max 5 policies per container/share Hard Used to revoke or manage active SAS tokens without changing storage account keys.
Containers per Storage Account No limit on the number of containers Soft Scalability is limited by total account capacity (5 PB) and transaction limits rather than container counts.
Blob Size Limit Max 190 TiB for block blobs (via Put Block/Put Block List) Hard Single block uploads are limited to 4 MiB to 500 MiB depending on tool and version.

Operational Restrictions & Key Metrics:

  • Redundancy Targets: LRS (3 copies in 1 DC), ZRS (3 copies across 3 AZs), GRS (6 copies across primary & paired secondary regions). Read-Access (RA-GRS) allows read access on secondary location.
  • SAS Types: Service SAS (single service), Account SAS (multiple services), User Delegation SAS (secured via Microsoft Entra credentials).
  • Blob Tiers: Hot (frequent access), Cool (min 30 days retention), Cold (min 90 days retention), Archive (offline, min 180 days, rehydration takes several hours).
  • Object Replication: Requires General Purpose v2 (GPv2) storage accounts and block blobs with versioning enabled on both source and destination accounts.
Compute (20–25% of Exam)
VM & Compute Quotas ↗
Resource / Concept Limit / Quota Type AZ-104 Exam Focus
Default vCPU Cores 10–20 vCPUs per region Soft Quotas apply per region and VM SKU family (e.g., Dv4, Ev4).
Availability Sets Max 3 Fault Domains, 20 Update Domains Hard Provides 99.95% SLA. Existing VMs cannot be added to an Availability Set post-creation without recreating.
ARM / Bicep Template Size Max 4 MB JSON size; 800 resources Hard Use linked templates or Bicep modules to break up deployments that exceed limits.
Deployment History Max 800 deployments per Resource Group Hard History auto-deletes when approaching limit, but clean scripts are recommended for automated deployment pipelines.
App Service Slots Standard (5 slots), Premium (20 slots) Hard Free and Basic App Service plans do not support deployment slots or autoscaling.
Managed Disks per Region Max 50,000 disks per subscription Soft Includes OS and data disks across standard HDD, standard SSD, premium SSD, and ultra disks.
Data Disks per VM Size Up to 32, 64, or 128 data disks (depends on VM size) Hard Larger VM series support higher maximum data disk attachments and higher IOPS/throughput.

Operational Restrictions:

  • VM Move Restrictions: VMs can move across Resource Groups or Subscriptions, but cross-region moves require Azure Resource Mover or manual redeployment.
  • Virtual Machine Scale Sets (VMSS): Up to 1,000 instances for platform images, 600 for custom images. Supports metric and schedule autoscaling.
  • VM Disk Resizing: Premium SSD and Standard SSD disks can be resized upwards without deleting the VM, but the OS partition must be expanded inside the guest OS afterwards.
Networking (15–20% of Exam)
Networking Limits & Quotas ↗
Resource / Concept Limit / Quota Type AZ-104 Exam Focus
Reserved Subnet IPs 5 IPs per subnet (First 4 + Last 1) Hard For 10.0.0.0/24, usable host range is 10.0.0.4 to 10.0.0.254.
NSG Rules Max 1,000 rules per NSG Hard Priority range is 100 to 4096. Lower numbers are evaluated first.
VNets & Subnets Max 1,000 VNets, 1,000 subnets per VNet Hard Peered virtual networks cannot have overlapping IP address spaces.
Public IP Addresses 1,000 per region per subscription Soft Standard SKU IPs are static by default. Basic SKUs are deprecated.
Application Gateway Backend Pools Max 100 backend pools per Application Gateway Hard Essential for routing traffic to multiple backend services using path-based or multi-site hosting rules.
User-Defined Routes (UDRs) per Route Table Max 400 routes per route table Hard Route tables can be associated with multiple subnets within the same virtual network.

Operational Routing & Network Security Rules:

  • VNet Peering: Transitive peering is not enabled natively. (If A is peered with B, and B with C, VNet A cannot communicate directly with VNet C without a Gateway/NVA).
  • User-Defined Routes (UDRs): Override default system routes. Traffic routes according to the Longest Prefix Match (LPM) rule.
  • Private Endpoints vs. Service Endpoints: Service Endpoints secure traffic via public endpoints over the Microsoft backbone. Private Endpoints create a Private Network Interface (private IP) inside your subnet.
  • Load Balancer (SLB) vs. Application Gateway: Standard Load Balancer operates at Layer 4 (TCP/UDP), whereas Application Gateway operates at Layer 7 (HTTP/HTTPS) supporting cookie-based session affinity and SSL termination.
Monitoring & Backup (10–15% of Exam)
Azure Monitor Service Limits ↗
Resource / Concept Limit / Quota Type AZ-104 Exam Focus
Log Analytics Data Retention Default 30 days (up to 730 days) Soft Retention can be extended per workspace or archived to Azure Storage.
Metric Alert Frequency Evaluated down to 1 minute Hard Metric alerts process much faster than Log Search query alerts.
Recovery Services Vault VM Limit Max 1,000 VMs registered per vault Hard Deploy additional vaults to scale beyond 1,000 protected VMs.
Site Recovery (ASR) RPO Down to 30 seconds for VMs Hard Replication frequency and retention points configured in replication policy.
Azure Backup Retention (Recovery Services) Max 9,999 recovery points per protected instance Hard Long-term retention policies can span daily, weekly, monthly, and yearly backups.
Action Groups per Subscription Max 2,000 action groups per subscription Soft Action groups define notification channels and automated triggers for alerts.

Diagnostics & Troubleshooting Tools:

  • IP Flow Verify (Network Watcher): Tests packet filtering to determine if NSG rules allow or deny inbound/outbound traffic to/from a VM.
  • Connection Monitor: Checks real-time end-to-end connectivity, latency, and hop paths between VMs or IP endpoints.
  • Action Groups: Reusable alerting targets supporting Emails, SMS, Azure Push, Webhooks, Logic Apps, and Automation Runbooks.
  • Alert Processing Rules: Used to suppress, silence, or route action groups dynamically during maintenance windows without modifying individual alert rules.
